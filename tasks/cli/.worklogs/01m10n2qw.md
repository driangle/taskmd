## 2026-08-27T18:57:43Z

Started. Read `apps/cli/internal/cli/get.go`, `internal/worktree/overlay.go`, and the
existing overlay read views (`list_overlay.go`) to find the seam.

**Findings:**

- `runGet` resolves against `overlay.Local()` only (via `scanTasksWithOverlay`), so a
  sibling-only ID never reaches `resolveTask`.
- Sibling copies are already relativized to their own worktree's tasks dir by
  `buildWorktreeOverlay` → `RelativizeSiblingPaths()`, so a remote task's `FilePath` is
  display-ready but no longer resolvable against the local scan dir.
- `overlay.Get(id)` gives the merged `worktree.Task` with `Worktree`, `Branch`,
  `RemoteOnly` already populated — the provenance the task asks for is available.
- Subtask 5 (web/MCP detail) is already handled upstream: `web.findMergedTask` and
  `mcp.handleGet` both fall back to `overlay.Get`. CLI `get` is the only gap.

**Approach:** resolve against local tasks **plus** the overlay's remote-only tasks in a
single `resolveTask` pass, rather than local-first-then-fallback. One pass keeps
exact/filename/fuzzy and ambiguity semantics identical for free (a query matching both a
local and a sibling task errors the same way an ambiguous local query does), which is
what the third subtask asks for. Remote-only IDs cannot collide with local IDs by
construction, so exact-ID resolution for local tasks is unchanged.

**Decisions:**

- Resolved in one pass over local + sibling-only rather than local-first-with-fallback.
  Fallback would have silently preferred the local copy on an ambiguous query; one pass
  makes ambiguity behave identically regardless of which worktree candidates came from.
- `buildDependencyInfo` now runs over the same merged set. Without it a sibling-only
  task's dependencies/children would not resolve at all, and a local task's dep info
  would contradict `graph`/`board`, which already render `EffectiveTasks()`. With the
  overlay inactive the set is byte-identical to the local scan, so non-overlay repos are
  untouched. This is a deliberate, spec-aligned (§3) widening beyond "local tasks
  unchanged" when the overlay is active.
- Added `worktree.Task.Origin()` exposing the winning copy's `gitmeta.Worktree`, so the
  worklog of a sibling-only task resolves against the tasks dir that actually holds it.
  Without it `filepath.Join(scanDir, relPath)` would have pointed at the local tree and
  could surface a stale local worklog for a task living elsewhere.
- Collapsed the six-parameter `outputGet`/`buildGetOutput` chain into a `getView`
  struct rather than adding a seventh.
