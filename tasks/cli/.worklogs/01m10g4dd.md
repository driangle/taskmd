# Worklog: 01m10g4dd

## 2026-08-27T00:00:00Z

Started work on surfacing worktree exclusions in `next --explain` json/yaml output.

**Findings:**

- `runNext` (apps/cli/internal/cli/next.go) gets `worktreeExcluded map[string]string`
  from `overlay.RecommendationInputs()`; the reason is a preformatted sentence built
  by `(*worktree.Task).ExclusionReason()`.
- Only the `table` branch of `outputNext` calls `printWorktreeExclusions`, so json/yaml
  lose the provenance entirely.

**Approach:** add a structured `worktree.Exclusion{ID, Reason, Worktree, Branch, Status}`
and an `Overlay.Exclusions()` accessor; `RecommendationInputs` derives its map from it so
there is one source of truth. In json/yaml, wrap the payload as
`{recommendations, excluded}` only when `--explain` is set *and* the overlay excluded
something — otherwise keep emitting the bare array so existing consumers see no change.

## 2026-08-27T01:00:00Z

**Completed.**

- `internal/worktree/overlay.go`: new `Exclusion{ID, Reason, Worktree, Branch, Status}`
  and `Overlay.Exclusions()` (sorted by ID). `RecommendationInputs` now derives its
  `map[string]string` from `Exclusions()`, so the table sentence and the structured
  fields can never disagree. `Status` is the *effective* status (what the sibling holds).
- `internal/cli/next.go`: `runNext` carries `[]worktreeExclusion` through `outputNext`;
  `nextPayload` returns the bare `[]Recommendation` unless `--explain` is set **and**
  the overlay excluded something, in which case it returns
  `nextExplainOutput{recommendations, excluded}`. `printWorktreeExclusions` now takes the
  sorted slice (dropped its own sort). Removed the now-unused `outputNextJSON/YAML`.
- Tests in `worktree_overlay_test.go`: json + yaml explain assertions (full struct
  equality on the json one), plus a table-driven shape-stability test covering
  "overlay without --explain" and "--explain without overlay". Also pulled the repeated
  claimed-repo fixture into `claimedRepoWithSibling`.
- Docs: `apps/docs/guide/cli.md` (payload example + flag table) and spec §4.

**Decision:** wrapping only in the explain+overlay case is a shape change for that one
invocation, but it is what the task asked for and the alternative — always wrapping —
would break every existing json consumer.
