## 2026-09-11T15:30:00Z

Starting work on GitHub issue #19: scanner silently skips task files with malformed
YAML frontmatter, so `validate` reports success while a task vanishes.

**Approach:** Key-sniffing escalation, as agreed in triage:
- Parser: tag ParseError when frontmatter was present but YAML-invalid; carry raw frontmatter.
- Add sniffer for task-signature keys (`id:`, `status:`, `priority:`, `dependencies:`).
- Scanner: escalate sniffed parse failures into result.Errors (Scan + ScanArchive).
- validate: scan errors become validation failures (non-zero exit).

## 2026-09-11T16:10:00Z

Implementation complete.

**Decisions:**
- `ScanArchive` left unchanged: adding an error channel would break its
  signature (breaking SDK change for a corner case). Broken archived files
  still surface indirectly as missing-dependency errors.
- Unclosed frontmatter blocks are also sniffed (whole content passed to the
  sniffer), so a task file missing its closing `---` is reported too.
- `reportScanErrors` in the CLI no longer requires `--verbose` — scan errors
  are now real signal (broken task files), so list/board/etc. warn on stderr
  by default; `--quiet` suppresses.
- Spec: documented the sniffing contract in the Validation section; synced.

**Verified:** SDK + CLI unit tests, full e2e suite, lint, vet all pass.
Live repro of issue #19 with taskmd-dev: `validate` exits 1 naming the file,
`list` warns on stderr.
