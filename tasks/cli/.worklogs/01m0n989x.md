# Worklog: 01m0n989x — Extend worktree overlay to remaining read views and validate

## 2026-08-23T08:31:04Z

Started. Read spec §4/§8 and the existing overlay layer (`worktree_overlay.go`,
`worktree_mode.go`, `list_overlay.go`, next/list wiring from 0acfb13).

**Findings:**

- All target views scan through `scanTasks` (board, stats, graph, report, phases,
  get) or `scanActiveAndArchived` (tracks, next); `validate` scans directly to
  control error output. There is no `metrics` command — the spec's "metrics" is
  covered by `stats`/`report` (sdk `metrics.Calculate`), so nothing separate to wire.
- The §8 duplicate-attribution has to happen *before* `warnDuplicateIDs` fires,
  which today runs inside `scanTasks` before the overlay is built — so the scan and
  the overlay build need to be one step for overlay-aware commands.

**Approach:**

1. `worktree_overlay.go`: store the copies index and the attributed local task list
   on `worktreeOverlay`; add `effectiveTasks()` (merged list with effective status
   substituted) and `worktreeCopies(id)` (per-copy status/owner/branch for `get`);
   make `Warnings` structured (`TaskID` + message) so validate can emit them as issues.
2. `worktree_mode.go`: in `buildWorktreeOverlay`, attribute local-scan copies whose
   path lies inside a sibling worktree root to that worktree (§8, drop them — the
   sibling's own scan already has them); move warning printing out to callers.
3. New `scan_overlay.go`: `scanTasksWithOverlay` (scan + overlay + post-attribution
   duplicate warning), `scanTasksEffective` (for status-aggregating views),
   `scanActiveAndArchivedWithOverlay` (for next/tracks).
4. Wire: board/stats/graph/report/phases → `scanTasksEffective`; tracks/next →
   `scanActiveAndArchivedWithOverlay`; list/get → `scanTasksWithOverlay`; get grows a
   `Worktrees:` section (text + additive `worktrees` field in json/yaml); validate
   prunes attributed copies before `v.Validate` and merges overlay warnings as
   LevelWarning issues.
5. Unit tests per view in `worktree_views_test.go` (stubbed sibling discovery, same
   pattern as `worktree_overlay_test.go`); e2e spot-checks for board and get in
   `internal/e2e/worktree_test.go`.

Provenance decision: aggregate views (board/stats/graph/report/tracks/phases) get
effective status only — per-row provenance stays in list/get/next-explain, matching
the spec §4 table.
