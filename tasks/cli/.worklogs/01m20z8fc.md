Triaged and fixed. Every symptom in the report reproduced against `a03dc9f` before

**Scope correction found during triage:** the report says `tags` "uses a different
path and is not [affected]". It uses a different function, but `applyTagUpdates`
carried the *same* defect independently — same key-line `[` test, same `- `-only
consume loop. Verified `set --add-tag` corrupted a multi-line flow `tags` exactly
like the other three fields. So the bug spanned four fields across two duplicated
functions, not three fields in one.

**Approach:** rather than patch both copies, extracted the shape handling once into
a new `sdk/go/taskfile/listfields.go`:

- `findListField` locates a field and measures the *full extent* of its value
  (`keyIdx`..`endIdx`), distinguishing flow / block / scalar. Tracking the real
  extent is the whole fix — the old code rewrote the key line and left the rest
  behind as an orphan.
- `scanFlow` walks from the opening `[` to the matching `]` across lines, ignoring
  brackets inside quotes, so the Prettier form (bracket on its own line, trailing
  comma) is consumed correctly.
- `replaceListField` / `listFieldLines` splice the replacement over that extent,
  preserving the shape the field already had so block sequences stay block.

All four entry points — `parseCurrentListField`, `parseCurrentTags`,
`applyListFieldUpdates`, `applyTagUpdates` — now route through it. That fixes the
read path (symptom 2: `--add-*` silently dropping existing values) and the write
path in one place. `taskfile.go` dropped 580 → 479 lines.

**Decisions:**

- Kept the `tags` quirk that an empty result leaves `tags: []` while the other
  fields remove the key — that is pre-existing behavior, expressed explicitly as
  an `emptyMode` rather than left implicit.
- Added the write-back guard (report item 5) rather than deferring it: acceptance
  criterion "no `set` invocation can leave a file taskmd cannot read" requires it.
  `UpdateTaskFile` re-parses the frontmatter it is about to write and refuses,
  with a report-this-bug message, instead of writing. It is a backstop for the
  *class*, not this instance.
- Left item 6 (`validate` reporting skipped files) out — the report itself says to
  file it separately, and `01m1sxgbz` already covers that gap. See open items.

**Tests:** table-driven in `sdk/go/taskfile/listfields_test.go` over every shape
