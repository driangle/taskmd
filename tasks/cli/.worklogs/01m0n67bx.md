## 2026-08-23T02:00:00Z

Implementation complete. Summary of what landed:

**New package `internal/worktree`** — the overlay merge layer extracted from
internal/cli (Task, Overlay, Merge, Builder with injectable Discover seam,
SiblingOnlyError guard). internal/cli keeps thin aliases and its viper-bound
mode resolution; all existing CLI worktree tests pass unchanged except merge-
level tests, which moved to the new package.

**MCP** — NewServer takes a worktree.Builder (resolved from --worktrees/
config in cli/mcp.go). list/get/status serve additive provenance fields
(effective_status, effective_owner, worktree, branch, remote_only, worktrees
copies); next uses overlay exclusions; search/graph/validate operate on
effective tasks; set returns the sibling-only guard error. Plugin taskmd-mcp
bumped 1.0.0 → 1.1.0 (additive tool surface, ADR 0003).

**Web** — DataProvider caches the overlay and re-discovers siblings on every
rescan (membership fallback). /api/tasks + detail carry additive fields;
board/graph/stats/next/tracks/search serve effective status; validate merges
divergence warnings; PUT returns HTTP 409 with the guard message. Watcher
gained SetDirs + meta dirs: sibling tasks dirs are watched on the same
debounce/SSE path, and <common-dir>/worktrees (or its parent while missing)
triggers re-enumeration without a restart. Static export bakes effective
status/provenance; single-worktree exports unchanged.

**Verification:** full unit suite, e2e suite, and lint all green. Manual check
against a real two-worktree repo: /api/tasks shows effective_status +
worktree, /api/next skips the sibling-claimed task, PUT on a sibling-only ID
returns 409 with the spec's guard message.

**Decisions:** payload shape anchored on CLI `list --format json` (status
stays local; effective_* additive). Sibling file paths stay absolute on
server surfaces (so worklog lookups on remote-only tasks resolve); only the
CLI relativizes them for display.
