## 2026-09-01T20:33:51Z

Suite built and piloted. The pilot paid for itself twice over — it caught one harness bug
and one grader bug that would both have corrupted the headline numbers.

**Built:** `evals/list-tasks/` with `workspace/` + `workspace-bare/` forked from
`evals/fixtures/`, a stdlib-only grader module in `workspace/.verify/` (mirrored into
`workspace-bare/.verify/`, as add-task does), and `suite.yaml` with five evals × four
variants. Each eval runs `agent_exits_ok` → `tool_not_used` → `no-mutation` →
`check_output`.

**Bug 1 — skival rewrites a relative first token (harness).** Every `check_output` failed
with `sh: <suite-dir>/cd: No such file or directory`, exit 127. A three-way probe suite
settled it: skival resolves a **relative** first token in `run:` against the *suite*
directory, so the bare `cd .verify && …` that `add-task`'s `check` steps use becomes
`<suite-dir>/cd`. The probe also confirmed the good news — cwd *is* the per-sample workdir
and stdin *is* the agent's final text. An **absolute** first token is passed through
untouched, so every command is now `/bin/sh -c 'cd .verify && …'`. That form also works on a
skival that does no rewriting, so it is forward-compatible either way. Worth documenting in
`evals/README.md`.

**Bug 2 — the grader failed a correct answer (mine).** `list-phase-filter` / `no-skill`
produced a correct mvp table and then closed with:

> The other two tasks (006 export CSV, 004 update README) are in the **Polish** phase, not MVP.

Both excluded IDs appear *with* title tokens and no cue word ("not MVP" is not "excluded"),
so the exact-set check reported them as leaked results. Chasing this with more cue words is
a losing game — the next agent phrases it differently, and `evals/README.md` says to match
stable tokens, not prose. Fixed **structurally** instead: if an answer contains two or more
list items (table row, bullet, heading — anything starting with the ID), only those lines
count and prose is treated as commentary; if it contains none, the answer is prose and the
window match applies. The two-item threshold matters — wrapped prose can start a
continuation line with an ID by accident, and a one-item threshold misgraded a prose-only
answer.

**Verification so far:**

- `workspace/.verify/output_test.go` — every output grader exercised both directions
  (17 cases) at zero token cost via `cd .verify && GOWORK=off go test ./...`. Both pilot
  bugs are pinned as regression cases, using the verbatim text that broke them.
- `no-mutation` hand-tested in all four directions (pristine passes; status flip, added
  task and deleted file each fail with a readable diff).
- All 20 pilot outputs re-graded with the fixed grader and read by hand. Four failures
  remain and **all four are genuine**: two agents (`no-skill`, `bare-project` on
  `list-status-filter`) refused to look at the project at all and asked which tasks were
  meant; `plugin-skill` answered the JSON eval with a markdown table while claiming "Full
  JSON output shown above"; `bare-project` broadened "high priority" to include `critical`.
- Tool-leak audit of the pilot conversations: **clean**. Per-variant profiles are exactly
  as designed — `plugin-skill` Bash-only, `lite-skill` Read/Glob, `bare-project` Bash/Read/Grep.

**Ordering change the pilot prompted:** `no-mutation` now runs *before* `check_output`. The
pipeline short-circuits on first failure, so with the old order a sample that both answered
wrong and damaged the fixture would only have reported the wrong answer.

## 2026-09-01T23:00:14Z

Done. Full run at **8 samples** (user chose 8 over the planned 5 after the pilot revised the
cost estimate down): 160 samples, 18m 54s, **$22.11**.

**Results:** `lite-skill` 100%, `no-skill` 80%, `plugin-skill` 77.5%, `bare-project` 65%.

**The headline: the old "0% delta" verdict for this skill was wrong**, and the reason is
instructive. It concluded the skill adds nothing because Claude finds `taskmd` on `PATH`
anyway. Finding the CLI was never the hard part. 22 of the 31 failures are things that harness
never probed:

- **14 failures — "my tasks" resolves to Claude's own memory, not the project.** Perfectly
  consistent: *all 14* ran exactly one command, `cat ~/.claude/projects/<slug>/memory/MEMORY.md`,
  found nothing, and asked the user where their tasks live. Not one ever ran `ls` or touched
  `tasks/`. It is **phrasing-dependent, not project-dependent** — the same `no-skill` variant in
  the same workspace scores 8/8 on "show me all my tasks" (where it immediately `ls`es, reads
  `TASKMD_SPEC.md`, runs `taskmd list`) and 2/8 on "which of my tasks are still pending?".
  Project vocabulary ("the mvp phase", "the CLI") grounds it; generic assistant vocabulary
  ("still pending", "high priority") does not. Either skill eliminates this entirely — zero
  mode-A failures between them. **That is the skill's real measured value.**
- **8 failures — the plugin skill makes the agent worse.** `list-json-format` 0/8: it runs the
  right command, gets correct JSON, re-renders it as a markdown table, and signs off with "Raw
  JSON is above in the tool output" — which the user cannot see. `no-skill` scores 6/8 on the
  same eval. The skill's whole instruction is "Present the output to the user."

Excluding the JSON eval, `plugin-skill` is 97% against `no-skill`'s 81% — so the 77.5%
headline mis-ranks it in both directions, and the report says so explicitly.

**Third grader bug, found while classifying failures.** One `bare-project` answer labelled rows
by group path (`web/003`, `cli/001`); the list-item anchor only accepted a bare ID, so those
rows were silently dropped. Fixed, pinned as a regression case, and **all 160 recorded outputs
re-graded: zero verdict changes**. Every number in REPORT.md is unaffected — reported as a
robustness fix, not a correction.

**Integrity checks, all clean:**

- `no-mutation` passed **160/160** — nothing edited a task while answering a question about
  one. `Write`/`Edit` were deliberately left reachable so this could fail; it never did.
- `tool_not_used` passed 160/160, and an independent manual census of all 160 conversation logs
  found only `Read`/`Bash`/`Glob`/`Grep`. Per-variant tool profiles confirm the variants really
  differ: `plugin-skill` Bash-only, `lite-skill` Read×241/Glob×57.
- All 31 failures are `check_output` — no step-type contamination.
