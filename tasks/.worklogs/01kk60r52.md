## 2026-09-03T08:30:00Z

Full run done and written up. Run 1 = commit `3081927`, 160/160 samples, **$20.34**, 18m52s.

**Note on running it:** `run-eval.sh` takes ~19 min and the Bash tool caps at 10. The first
attempt was killed at the cap and lost the whole run — no results directory, no partial
output, real spend for nothing. Re-launched with `run_in_background: true`, which is the only
way to run a full suite here.

**Result** (after grader corrections): `plugin-skill` 100%, `lite-skill` 100%,
`bare-project` 80%, `no-skill` 77.5%.

**Three more grader bugs, all found in the post-run audit, all false negatives, all in
`get-missing`:**

1. The not-found cue list had "no task" but not "don't see" — failed *"I don't see a task
   042 in this project"*.
2. The mislabel span broke on sentence punctuation only, so *"no task 042 — the highest task
   ID present is 006 (…006-export-reports-csv.md)"* read as 006 mislabeled as 042. The span
   now also breaks on **another task ID**.
3. `missingIDPattern` consumed the sentence-ending period, so the forward span started past
   it and swallowed the next sentence — failed *"There's no task 042. The closest match is
   002: Add full-text search."* Now captures the digits and addresses them directly.

Re-graded all 160 recorded outputs against the fixed grader: exactly those 3 flipped, nothing
else. `check_output` sees only the agent's final text, so re-grading recorded text is exact —
both as-run and corrected numbers are published so the correction is auditable.

**The one real finding:** `get-by-keyword` is 0/8 for `no-skill` *and* `bare-project`, 8/8
for both skills — the whole 22.5-point delta. All 16 failures are the `list-tasks` pathology:
the agent answers from `~/.claude/.../memory/MEMORY.md`. One `bare-project` sample said the
workspace was "a fresh, non-git working directory with no files in it" with six task files in
`tasks/`. Meanwhile `get-by-id` ("show me the details of task 003") is 8/8 for *everyone*,
including the variant with no CLI and no docs. Phrasing decides it, not difficulty.

**Recorded honestly:** four of five evals are at the ceiling for all four variants, so one
eval carries the entire result; `plugin-skill` vs `lite-skill` and `bare-project` vs
`no-skill` are both unresolved at this sample size. No tool leakage (census across all 160
conversations is Bash/Read/Glob/Grep only); `no-mutation` passed on every sample.
